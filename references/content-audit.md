# 内容查漏补缺：素材 → 卡文的覆盖审计

> 触发：结构（7 字段／槽位／嵌图）都修完了，用户说「里头的文字要查漏补缺」「内容不全」「把设定补进去」。
> 这一步与「精修」不同：精修管**格式与声线**，本档管**设定覆盖**——素材里有的、影响扮演的东西，卡里是不是漏了或写错了。

## 一、素材四源（缺一源就会漏）

| 源 | 路径（素材仓内） | 供什么 |
|:--|:--|:--|
| personas 三件 | `personas/<角色>/{IDENTITY,persona-soul,AGENTS}.md` | 声线、性格锚点、对话节奏、边界（卡文多半已覆盖） |
| curated 精炼档 | `curated/01-characters/NN-<角色>.md` | 基础资料表、关系、深层设定、外观段 |
| 角色设定档 | `characters/<作品>-<全名>-角色设定.md` | 官方 1-5 节 ＋ **社区考据节**（编号帖）——细节与强情感点基本都在这 |
| skin 档 | `skins/<系列><角色>.md` | 当前卡图那套衣服的外观描述（换图后必看） |

## 二、先出一张样板，口径点头再铺开

整库 16 张一起改，粒度拍错的返工量是 16 倍。先挑一张（最轻或最有代表性）做完整清单，交用户核三件事：**该不该收这类细节／补到哪个槽／上限多少**。点头后再并行铺开。

## 三、清单四分类（每类一张表，别混）

1. **真缺口**——素材有、卡里没有。列：内容 ｜ 来源层级（官方／考据）｜ 建议槽位 ｜ 一句话理由
2. **写错／矛盾**——卡文与素材不符，或**卡文与当前卡图不符**（换过立绘系列的卡必查）。列：卡里现在写的 ｜ 素材实际 ｜ 出处文件:行
3. **已有但偏薄**——不算缺口，只作可选加强；用户没点头就不动
4. **不计入**——刻意不补的连同理由落档；不记，下一轮会当漏项再补回来，一次减法就白做

## 四、判据

- **只补影响扮演的**：身份／年龄／生日／身高、人物关系、口癖与腔调、秘密与忌讳、身体能力、鲜明的癖好细节。CV、外文名、体重这类档案字段不收。
- **每张 ≤150 token**（恒定口径）。设定表整张搬进卡＝把预算喂给没用的行。
- **官方 ≠ 考据**：考据节是玩家整理，写进卡可以当她的习惯，但清单里必须标「考据」，不许在汇报里说成官方设定。
- **每条带出处**（文件＋行号或小节名）；查不到就写「库内无证据」，**不许编**——编的缺口会变成编的卡文。
- **落点分槽**：标签进 `description`、身份关系进 `personality`、深锚进备注（`depth_prompt`）、可演规则进 `system_prompt`、忌讳与反应进 `post_history`。全塞 description 会把它撑爆。

## 五、批量怎么派

按**卡**切文件集（不是按主题），每路子代理 3-4 张，任务书七件套照 `delegation-and-verification`：

- 交付物：每卡一份 `workspace/records/tavern-card-audit/<卡名>.md`，模板用上面四分类的表头
- 禁止：改任何卡 JSON、改素材（只读）
- schema：每卡各几条真缺口、写了几份文件、路径
- 回来先**抽验 2-3 条出处行号**能不能对上再采信——子代理会为凑数把相近设定写成缺口
- **审计表里的判断也是自报，采信前回原档核一遍**。三类实测过的假信号：① **字段路径读错**——把 `data.character_book` 读成 `data.extensions.character_book`，报「卡内书为空」；② **引用当无证**——某句被标「库内无证据」，实际就在角色设定档里被原文引用过一次；③ **两档互指**——两个素材档对同一昵称的指向相反（谁叫谁），别就近采信，回官方语言表看原句是谁的口癖。删原句之前先确认它真的无据，误删一句原文的代价比多留一句大。
- 全部清单回来、用户点头后，**由主线统一写入卡**（别让子代理直接改卡：并行写同库必撞车）

## 六、写回顺序

内容补齐 → 槽位归位 → 备注收敛 → 嵌 PNG → `tavern verify`。内容先定时，归位工具才能把新内容搬到对的格子；反过来做就是搬完再拆一次。

## 七、坑

- **换立绘系列后必查重复一项**：`[body= …]` 是旧系列写法（实测 16 张全中）——这条不看素材也会中，但只有把 skin 档放进素材清单才会被查出来。
- **「已有但偏薄」不要偷偷补**：审计表里单列，用户点头才动，否则一次补丁就把 token 预算吃掉。
- **别把考据当官方写进 `system_prompt`**：硬规则里写了玩家梗，模型会当作正史反复演。

## 八、世界书也在这条链上（别只查卡）

「查漏补缺」的范围是**卡 ＋ 世界书**，不是只有卡。用户提一句「世界书」或在测触发，多半是在提醒这件事；只回一句触发测试结果＝没接住。

同一套「素材 ⇄ 成品」对照法，分两层查：

| 层 | 成品 | 素材 | 查什么 |
|:--|:--|:--|:--|
| 世界层 | `条目清单.json`（机构/地点/机制/术语） | `setting/` 整套（大世界、机构信息、各组织 txt、彩蛋轶闻录…） | 素材里成体系、且日常对话会聊到的设定有没有条目；条目内容与素材有无冲突；关键词漏词/误触发 |
| 关系层 | `关系清单.json`（每条挂一张接收卡） | `characters/*.md` 的「人物关系」章节 ＋ 各卡 persona | 按接收卡做**覆盖矩阵**：这张卡该知道的那些人，条目里有没有；同一卡同一对象是否重复成多条 |

- 审计产出与卡文分开落档：`workspace/records/worldbook-audit/世界层.md`、`关系层.md`，表头照本档第三节四分类（真缺口／写错／偏薄／不计入）。
- **按层切路委派**：世界层一路、关系层一路，只读；回来先抽验几条出处再采信。
- **写回顺序**：改清单 JSON（`条目清单.json` / `关系清单.json`）→ `wb new 条目清单.json 关系清单.json --out 书.json` 重建 → `wb sim` 正反验收（该触发的命中、无关话术 0）→ 再登记。别手改生成出来的书文件。
- **判「官方原话怎么说」用语言表频次，不靠设定档转述**：`sources/语言表/lang_official.txt` 是官方文案逐字表，拿 `grep -c` 对比两种写法就见分晓（实测：`O·T·E` 214 处 vs `O.T.E` 3 处；`RoSE` 是官方简写而设定档转述里混进了 `Ro'S`；`第一尖端研究小组` 三处全中、`第一尖端研究所` 零命中）。世界书条目、卡文、关键词都按这个口径定，wiki 转写与设定档只是线索。
- **关键词里的裸词会按子串吃一切**：`研究所` 会把「拉马克研究所」一起灌进结构研究所条；`可可` 是饮品词；`4号`/`7号` 会撞日期。加键前拿 `wb sim <卡> "真句子"` 跑正反两面（该命中的命中、无关话术 0），别凭感觉。
- **关系条的键要包含对话里实际会用的称呼**，不只全名：只挂「苏小真／小真」时用户说「小明星」不触发，得把专属称呼也列进 keys。
- **开场寒暄注入 0 不是故障**：全书 0 常驻时 `wb sim <卡> "你好"` 必然 0 token——只能说明没有常驻条目，不代表书没接上。要判「书有没有在工作」，用一句会命中主键的话（「今天咖啡馆的客人真多」→ 命中咖啡馆一条）。**要不要让世界观常驻是设计题，交用户拍**（实测：咖啡馆一条 86 字≈103 token），不擅自把 `constant` 打开。
