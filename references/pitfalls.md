## 踩坑


- **多阶段出身要写成一条时间线**：角色同时有几种来路（出身地／历练地／现在的单位）时，**只并列写会逼模型在问到过去的那一刻现场选边**——实测样本把它判成「三个身份不能同时成立」并为此停了一次。写清次序（「来路是连着的，不是三个身份：A 出生 → B 历练 → 现在在 C」）一句话消掉整类卡顿。
- **助手型／服务型角色要补两条边界**（把卡当工具用的用户必然撞上）：① **能力边界**——写清它做不了什么（查资料／写代码／解难题）并给处置口径（直说不会、不装懂、转成陪伴）；不给边界，模型只能「绕」，绕两次就是复读机。② **元问题口径**——被问「你是不是 AI／是不是程序」时不正面答、**也不装作听不懂这个词**（那是表演性降智），用「我是什么」来答再把话带开。

- **别拿官方示范卡当「字段该放哪」的判据**：官方默认卡（Seraphina）把示例写在 `description` 里、`personality`/`scenario`/`mes_example` 三格全空——那是**兼容形状**，不是最优形状（示范卡没跟上引擎后来给示例／场景单独开的槽）。字段摆放要问引擎怎么用它：读 `references/slot-mechanics.md`（注入位置＋是否吃恒定预算），不读示范卡。照抄示范卡会把「描述框身兼多职＋恒定 token 白烧」当成规范。
- **PList 顺序（2026-09-16 定案）**：Trappu 口径 `body→Setting→Personality`，「最重要的放最后」。此前拿一张自己就写反的卡当范例，把 9 张卡一起带偏，已全库归一。validator 不查顺序——只有 `check_refined_card.py` / `tavern plist` 抓得到。
- **去重原则**：与 post_history_instructions 重复的规则删 PList 侧（同一信息保留最近的职责位）；断言脚本的 >16 字标签检查能顺带抓出这种重复长标签。
- **归位＝复制 ⇒ 必生重复**：槽位归位把 PList 内容复制进各专槽、备注又原样留着，同一份信息就三处并存——归位当天只算了「恒定降」，重复那笔账是用户在酒馆里回头翻出来的（《酒馆问题汇总v2》）。**归位之后必跟一步「备注收敛」**（上一节），交付说明里写清「每条内容只有一个正主」。
- **工具里的版号白名单会过期**：`bin/tavern list` 的 `refined` 判定写死 `ver in ("0.2","0.3")`，v0.4/v0.6 的卡全被报成「未精修」——白名单写成区间（`0\.[2-9]`，与 `check_refined_card.py` 同口径），别枚举当时已知的版本号；同一份口径出现第二处实现就是该收口了。
- **程序化拼 `<START>` 双括号**：素材里 user 行自带「」，f-string 再包 `「{line}」` → 产出「「...」」。素材行已含全角引号时拼接不要再包一层（2026-08-26 批量精修实测踩中，修完要重跑 validate + 复核脚本）。
- 改卡脚本打印成功 ≠ 文件真改好——`git diff workspace/tavern-cards/` 确认改动存在后再 commit。
- **比卡先归一换行**：`\r\n` → `\n` 再逐字段比。V3 导出卡常常整篇 CRLF，直接 diff 会得到满屏假差异（长度差全是换行符），`check_refined_card.py` 两个 prompt「以 `{{original}}\n` 开头」与 first_mes 单换行断言也会因此判 FAIL——修法是把卡转成 LF，不是改断言。
- **同名字段类型漂移**：跨 spec / 跨来源的同名字段类型可能不同（`extensions.talkativeness` 数字 `0.5` vs 字符串 `"0.5"`；`group_only_greetings` 缺失 vs `[]`）。归一化比对时类型差异要单独列，别混进「内容不同」。
- **比对直接用工具**：`scripts/diff_cards.py <A.json> <B.json> [--full]` 一把出「实质不同 / 仅换行差异 / 类型漂移 / 顶层与 extensions 键差集」，别每次手写临时 python。
- **卡内 character_book 的隐形门槛（源码实证）**：`selective: true` + 二级键 = 「主键 **且** 任一二级键」才触发（默认 AND_ANY），门槛远高于卡面观感；卡里那 19 条已用 `bin/wb unfilter` 修掉（二级键并入主键／泛词剔除）。只想要「任一词触发」就别写 `secondary_keys`。另：book 级 `scan_depth`/`token_budget`/`recursive_scanning` 引擎不读，是摆设。详见 `sillytavern-worldbook/references/12-worldbook-mechanics.md`。
- **卡内书条目不是「删掉泛词键」就算修好**——条目进 prompt 有五层可控点：来源分组（`character_strategy` 默认 `character_first`，卡内书整体先于独立书）→ 扫描源（`scanDepth` ＋ `match_*` 六类附加源）→ 触发（`@@activate`/`@@dont_activate`、constant、主键、二级键、概率、包含组）→ 组内 order → 注入（`position` 七桶 ＋ `depth`/`role`）。动卡内书前先读 `sillytavern-worldbook` 机制**主档 §0「一次生成的调用链」**（`sillytavern-worldbook/references/12-worldbook-mechanics.md`；递归/包含组/过滤器等特殊机制在附档 `sillytavern-worldbook/references/12b-mechanics-advanced.md`），先定三层再谈键：**靠什么进**（关系方专有名称 / 卡字段 `match_*` / 强制激活）· **放哪**（关系 `after_char`；禁忌情绪 `at_depth`）· **要不要常驻**（`constant` 每轮吃预算，每卡一条约 150-200 token）。
- **本体角色名当键＝隐性常驻**：扫描区每条聊天都带 `名字: ` 前缀（`include_names` 默认开），本体名每轮都在场，当键没有触发意义；「**关系方的**角色名」才是正路。**用户侧名字同理**（店长／指挥官／`{{user}}`几乎每条消息都出现）——「用户 ↔ 角色」的关系（依赖／救命恩人／相处模式）写**卡本体**（`post_history_instructions`／`system_prompt`），不占世界书。另：泛词键（老师／决定／过去／结构…）实测在无关句子里 4 发 4 中，确实要话题触发就改**短语键**或收紧 `scanDepth`。**单字键更险**：全文子串命中，`唯` 撞「唯一」实测 1/1 把整条 77 token 灌进去（键收成 `7号` 才干净）——键定完拿 `wb sim <卡> "真句子"` 试正反两面，别凭感觉。
- **重设计卡内书／关系条目前的四道核对**（缺一道就白改）：
  ① **字段核实**——「卡本体已经写了」必须指到具体字段（`description`/`personality`/`system_prompt`/`post_history_instructions`/`mes_example`/`depth_prompt`），别用「PList」当泛指；**本库多张卡 `personality`/`scenario`/`mes_example` 三格全空**，空字段不算载体，这种卡「减法」只剩去掉常驻条、关系层是净增，做不出厚卡那种降幅。
  ② **唯一载体**——删条目前逐条问「这条里的事实还有别处吗」；只剩这一处的先补进卡本体再删（例：某条独有的「养兄＝集团养子」），否则删条目＝信息一起没了；补本体是改卡 T1，先报再动。
  ③ **口径核对**——同一个人的事实可能有两套（前作／本作），素材仓 `prequel/` 的角色页自带「与…主要差异（吃书点）」表：**本作「未提及」的线写进本作卡＝凭空造设定**，只写能延续的那层，结局／动机交用户定。
  ④ **加料核对**——旧条目常带文档里没有的作者自补细节（「让她失去平衡」被写成「失去平衡**倒进店长怀里**」），按档案砍掉并在交付里点名，别默默留。
- **同键跨书＝加法，不是撞车**：卡内书与共用书撞同一个键（例 `结构研究所`）时两条都会进——一条答「这机构是什么」、一条答「她跟这机构的来处」，这是想要的；要消的是同一层里的重复键与跨卡误触发（`wb check`）。
- **设计稿阶段就带实测 token**：`worldbook_tools.token_count`（cl100k，与 `wb ls` 同源）逐条量，别估——估的普遍偏低（一批 5 条估 ≈420，实测 464）。
- **改已交付的卡（16 张）属 T1**：卡内书条目的批量改法先落「逐条改法清单（现键→建议键＋档案出处）」给用户拍，拍完再动手；对照依据在素材仓的 `personas/`（专属称呼、口头禅）与 `curated/01-characters/`（设定原句）。同一套口径要铺多张卡时，**先出一张样板**（带交付时的自查更正）等用户拍完再乘 N——模板错一处就乘 N。
